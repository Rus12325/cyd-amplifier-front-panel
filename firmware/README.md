# Прошивка панели усилителя для CYD (ESP32-2432S028)

Прошивка превращает плату в переднюю панель усилителя **5.1**: включает и выключает
шину 24 В, держит mute, показывает спектр музыки, обслуживает тач, хранит настройки
в NVS и умеет тестировать собственную обвязку.

Сборка, под которую написана прошивка: три стереоплаты на общей шине 24 В, БП
24 В / 4 А, источник — ПК с тремя аналоговыми выходами, два реле 5 В.

* подключение железа — [`../docs/wiring.md`](../docs/wiring.md),
* интерактивный гайд с симулятором — `../wiring_cyd_amp.html`,
* нетлист, собранный из таблиц — `../docs/wiring-netlist.html`
  (`python ../tools/wiring_diagram.py`; генератор намеренно отказывается писать
  в `wiring_cyd_amp.html`, чтобы не затереть гайд).

## Сборка и прошивка

```bash
cd firmware
pio run -e cyd -t upload        # панель 5.1: ПК-источник, шина 24 В, mute, громкость ПК по BT-HID
pio run -e cyd_enc -t upload    # то же плюс физический энкодер на GPIO 22/35
pio run -e cyd_bt -t upload     # плюс CYD сам принимает Bluetooth (A2DP; громкость ПК отключается)
pio run -e cyd_bt -t upload --upload-port COM7   # если номер порта сменился
pio device monitor -b 115200
```

Номер порта у этой платы не постоянный, а убитая программа может удержать захват
до перетыкания кабеля, поэтому есть вспомогательный скрипт: он находит CH340,
проверяет, что порт реально открывается, и только потом зовёт PlatformIO.

```bash
python ../tools/flash_cyd.py --list          # что подключено и свободно ли
python ../tools/flash_cyd.py --env cyd       # залить сборку 5.1
python ../tools/flash_cyd.py --env cyd_bt --wait 120   # ждать освобождения порта
```

Если порт занят навсегда (драйвер не отпускает захват), помогает перетыкание USB;
программная альтернатива — `tools/restart_cyd_port.ps1` от имени администратора.

Лог удобнее читать тем же способом: скрипт оставляет DTR/RTS в покое (DTR на этой
плате идёт на IO0 — импульс по нему вводит плату в ROM-загрузчик, и монитор
показывает пустоту) и делает обычный сброс через RTS.

```bash
python ../tools/serial_log.py --seconds 20      # сброс и лог загрузки
python ../tools/serial_log.py --no-reset        # просто слушать порт
```

Собираются все четыре среды: `cyd` — 17.0 % RAM / 93.2 % флеша, `cyd_enc` —
17.1 % / 92.8 %, `cyd_bt` и `cyd_bt_static` — 17.2 % / 93.1 % (обе тянут
библиотеки прямо из git, тег зафиксирован). Флеш занят под завязку в первую
очередь из-за Bluetooth: среда `cyd` грузит стек BLE, `cyd_bt` — A2DP. Свободных
~90 КБ хватает на правки, но если их съест, надо менять таблицу разделов
(`board_build.partitions`) на вариант с большим `app`, либо использовать
`cyd_bt_static` как есть без OTA.

## Что панель делает в сборке 5.1

| GPIO | Роль | Что происходит |
|---|---|---|
| 27 | реле K1 — шина 24 В | включается первым, после mute и паузы 1.5 с mute снимается |
| 16 | реле K2 — mute | замыкает шесть входных линий на землю; встаёт раньше, снимается позже |
| 22 | свободный ключ | прошивкой пока не переключается: тыл+саб, вентилятор или зелёный светодиод |
| 35 | съём звука | режимы `BARS`, `VU`, `SCOPE`, `OFF`, чувствительность в `METER GAIN` |

В сборке `cyd_enc` пины 22 и 35 отданы квадратурному энкодеру (см. ниже), и
съёма звука в ней нет — панель работает как пульт, спектр остаётся на второй плате.

Источник в меню один — `PC 5.1`: три джека ПК идут на входы плат напрямую, реле в
звуковом тракте нет, громкость живёт в Windows. Зелёный пин RGB-светодиода занят
mute-реле: драйвер светодиода сам пропускает пины, которые уже принадлежат
каналу, поэтому светодиод просто работает без зелёного (в сборке с расширителем
он остаётся целым).

Порядок коммутации (одинаковый для кнопки на экране и для кнопки BOOT):

```
вкл:  mute → реле шины → 1.5 с прогрев → снятие mute
выкл: mute → снятие 24 В → хвост 250 мс
```

Самопроверка при загрузке печатает, что нашла:

```
build        : cyd - 5.1 panel: PC source, 24 V bus + mute
pc volume    : BLE HID "Amp panel keys", volume up/down/mute keys
touch        : XPT2046, sclk 25 mosi 32 miso 39 cs 33
amp power    : GPIO27
mute relay   : GPIO16
spare key    : GPIO22
boards       : 3 x stereo on one 24 V bus, PC on three jacks
source       : PC 5.1 (wired straight to the boards)
```

## Громкость ПК с панели по Bluetooth-HID

Громкость в этой сборке живёт в Windows: ПК подаёт сигнал на входы плат джеками,
и никакого «усилительного» РГ в тракте нет. Поэтому панель притворяется
маленькой Bluetooth LE-клавиатурой (HID consumer control) и жмёт те же медиа-
клавиши, что и мультимедийная клавиатура: `Volume Increment` (0xE9),
`Volume Decrement` (0xEA), `Mute` (0xE2). **Ничего не распаивается и не
переключается** — это радио внутри ESP32, провода к ПК не нужны.

Сопряжение — один раз:

1. залить `cyd` (или `cyd_enc`), включить панель;
2. на ПК: «Параметры → Bluetooth и устройства → Добавить устройство»;
3. выбрать **`Amp panel keys`** (имя из `CFG_HID_NAME`);
4. Windows поставит «Just works»-сопряжение без PIN и подпишется на отчёты.
   Строка `pc keys` на экране диагностики сразу скажет, что вышло:
   `LINKED` — клавиши идут, `PAIRING` — панель ждёт сопряжения, `OFF` — стек не
   поднялся.

Управление на экране (вкладка с громкостью появляется вместо трек-полосы
A2DP, которой в этой сборке нет):

* три чипа `-` / `MUTE` / `+` в строке источника — одно нажатие = одна клавиша,
  удержание повторяет (первый повтор через 400 мс, дальше каждые 140 мс);
* полоса `PC VOL` под чипами — **тач-энкодер**: ведите по ней пальцем, и на
  каждые 9 пк шага отправляется клавиша; полоса ходит за пальцем в обе стороны
  без отрыва;
* физического энкодера в базовой сборке нет — пины кончились (см. ниже).

Чего панель не знает: HID только **отправляет** клавиши и никогда не спрашивает
текущий уровень. Число `PC VOL ~NN%` — оценка: она начинается с 50 % и едет на
один шаг за каждое нажатие, которое реально ушло в радио. Крутите громкость
мышью на ПК — оценка разойдётся, и это нормально.

Практические мелочи:

* нажатия копятся в очереди на 16 шагов: если крутить быстрее, чем BLE успевает
  отправлять, ничего не теряется, кроме переполнения (счётчики видны в логе);
* без связи нажатия не копятся «на потом» — они отбрасываются, чтобы после
  сопряжения в ПК не прилетел залп из двадцати шагов;
* клавиша держится 20 мс, пауза между клавишами 14 мс (стек BLE с одним отчётом
  не любит спешки);
* если в ПК громкость не двигается — проверьте, что Windows считает устройство
  клавиатурой, а не «неизвестным устройством»: удалите его и сопрягите заново.

### Физический энкодер (сборка `cyd_enc`)

У платы свободны только GPIO 22, 27 и 35, поэтому энкодер — обмен, а не подарок:

```
энкодер A  → GPIO 22  (был «свободный ключ», ключ в этой сборке перестаёт быть резервом)
энкодер B  → GPIO 35  (был съём звука; визуализатор в этой сборке остаётся без АЦП)
энкодер SW → не подключать: единственный кандидат GPIO 0 — это пин BOOT,
             зажатая при включении кнопка вводит плату в ROM-загрузчик (CFG_PIN_ENC_SW=-1)
```

Оба пина работают как входы: **обязательны внешние подтяжки 10 кОм к 3V3**
(у GPIO 35 внутренней подтяжки нет), каждая вторая ножка энкодера и его корпус —
на общий GND. Прошивка считает 4 перехода на щелчок, направление меняется
`-DCFG_ENC_REVERSE=1`, кнопка энкодера (если всё-таки на GPIO 0) — mute.

## Что умеет

* **Питание усилителя.** Реле на канале `CH_AMP_POWER` (GPIO 27), последовательность
  `mute → реле → 1.5 с прогрев → снятие mute`. Долгое нажатие на `POWER` —
  принудительное выключение. Есть опция `POWER ON BOOT`.
* **Mute.** `CH_MUTE` (GPIO 16) — жёсткий mute всех входных линий на время
  переключений и на время включения/выключения шины.
* **Визуализатор.** 16 логарифмических полос, режимы `BARS`, `VU` (шкала в дБ),
  `SCOPE`, `OFF`. 512-точечный FFT, окно Ханна, баллистика атака 15 мс /
  спад 250 мс, удержание пиков 1.2 с. Съём с АЦП — 8 кГц (полоса 40 Гц…3.6 кГц),
  из декодированного PCM — ~22 кГц (полоса до 10 кГц).
* **Тестовый тон** (сборка `cyd_bt`): 440 Гц тем же путём, что и музыка.
* **Калибровка тача** — четыре крестика по очереди; прошивка сама определяет,
  какой канал контроллера ведёт какую ось. На неоткалиброванной панели калибровка
  запускается от любого касания, а сырые отсчёты видны строкой `touch RAW`.
* **Настройки в NVS.** Яркость, авто-затемнение, режим, усиление индикатора,
  источник, включение при подаче питания, калибровка тача.
* **Авто-затемнение** подсветки через 60 с без касаний.
* **Светодиод RGB** как индикатор: зелёный — включено (в 5.1-сборке зелёного нет,
  см. выше), янтарный мигающий — идёт переключение, тускло-красный — дежурный
  режим, синий — играет Bluetooth.
* **Экран диагностики** (MENU → DIAGNOSTICS): состояния каналов одной строкой
  (`bus` / `mute` / `key` со своими `OK`/`FAIL`), имя вывода, частоты и полосы,
  размах АЦП, постоянная составляющая, свободная память, `RUN WIRING TEST`,
  а в сборке с громкостью — строка `pc keys LINKED vol ~64%` со счётчиком
  отправленных и потерянных шагов.
* **Проверка обвязки.** Кнопка на экране (только при выключенном усилителе) по
  очереди подаёт на каждый канал высокий уровень, читает линию обратно, отпускает
  и снова читает. Молчание линии означает неправильный вывод или вывод, занятый
  другим периферийным устройством. В логе каналы подписаны ролями:
  `ch0 GPIO27 bus OK`, `ch1 GPIO16 mute OK`, `ch2 GPIO22 key OK`.

## Режимы сборки

| Флаг | Смысл |
|---|---|
| `CYD_BLE_HID` | `1` — панель сопрягается с ПК как BLE-клавиатура и управляет его громкостью (по умолчанию `1`; в `CYD_BT_SINK`-сборках выключен принудительно) |
| `CFG_ENC_ENABLED` | `1` — поднять квадратурный энкодер на GPIO 22/35 вместо свободного ключа и АЦП (среда `cyd_enc`) |
| `CFG_ENC_REVERSE` | `1` — поменять направление вращения |
| `CYD_BT_SINK` | `1` — плата сама принимает Bluetooth и отдаёт звук через встроенный ЦАП на GPIO 26 (среда `cyd_bt`) |
| `CYD_BT_I2S_OUT` | `1` — вместо внутреннего ЦАП внешний I2S-ЦАП/усилитель; в 5.1-сборке пины по умолчанию конфликтуют с реле, поэтому пины I2S переопределяются: `-DCFG_PIN_I2S_BCLK=4 -DCFG_PIN_I2S_LRCK=17 -DCFG_PIN_I2S_DOUT=22` |
| `CFG_BL_FITTED` | переопределяется вручную, если I2S унесли с пина подсветки |
| `CYD_DAC_BOTH` | `1` — разрешить оба канала внутреннего ЦАП (по умолчанию только GPIO 26: GPIO 25 — клок тача) |
| `USE_IO_EXPANDER` | `1` — ключи висят на PCF8574 по I2C, каналов становится восемь: питание каждой платы отдельно, режимы «фильм / музыка / ночь», вентилятор, возврат зелёного светодиода |

Проверка арифметики визуализатора, раскладки экрана и таймингов переключения:

```bash
python ../tools/check_spectrum.py
```

## Ограничения и что дальше

* **Интерфейс на латинице.** Стандартные шрифты TFT_eSPI не содержат кириллицы.
* **Аналогового РГ по-прежнему нет** — и он не нужен: громкость делает сам ПК, а
  панель жмёт медиа-клавиши по Bluetooth-HID (сборка `cyd`). Так работает только
  с источником-ПК: у винила или CD-плеера громкость так не покрутить — там остаётся
  аналоговый путь (3 сдвоенных потенциометра на одной оси и печатная муфта) или
  цифровой (3 × PGA2311 с двуполярным питанием).
* **BLE-HID живёт только в сборке `cyd`.** A2DP и BLE делят один контроллер, и
  библиотека A2DP поднимает его в classic-only режиме, поэтому в `cyd_bt`
  громкость ПК отключена (`-DCYD_BLE_HID=0`, проверяется `#error` в `config.h`).
  Если панель должна и принимать Bluetooth, и крутить громкость, вариантов два:
  отдельная панель на втором CYD или библиотека A2DP, работающая поверх NimBLE.
* **Тест обвязки пока не отличает «пин не подключён» от «пин занят дисплеем»** — оба
  случая дают `FAIL`, различить помогает только список каналов в логе.
* **Режимов «фильм / музыка / ночь» нет** — для них нужен расширитель
  (`USE_IO_EXPANDER=1`) либо третий ключ на GPIO 22 и отдельная страница интерфейса.
* **Расширитель и A2DP несовместимы**: в `cyd_bt` не остаётся свободных пинов под I2C.
